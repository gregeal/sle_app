# OpenAI live dictation for the speaking partner

User feedback: device recognition misses words and produces inaccurate French;
retain the visible editable transcript and useful correction workflow.

## Implementation

- Explicit opt-in engine choice in the shared partner/solo response editor,
  remembered locally. Device dictation remains available with no silent fallback.
- Dedicated input-only OpenAI WebRTC transcription session, not a conversational
  Realtime model pretending to transcribe. No assistant response is generated by
  this session and the existing feedback/TTS pipeline stays unchanged.
- `gpt-live-transcribe`, French language hints, `delay: high`, near-field noise
  reduction, and verbatim learner-speech context. Accuracy must be assessed with
  real learner audio; the prompt cannot guarantee a perfectly literal transcript.
- Manual commit on Stop, provisional live deltas replaced by final wording,
  no silence-triggered submission. Capture limited to ten minutes; continuation
  appends to the preserved draft. Finalization has a bounded timeout and warns
  clearly on incomplete text; no automatic retry or second paid capture.
- Microphone muted during connection setup and finalization; cancellation drains
  media resources even when permission/connection operations complete late.
- Mobile uses its encrypted official-OpenAI key to obtain a short-lived secret;
  the browser uses the authenticated, CSRF-protected broker. Server-owned session
  configuration and existing budget/rate controls are retained. Older broker
  responses lack the transcription purpose marker and are rejected before streaming.
- No app-created audio recording files. OpenAI receives live audio before feedback
  submission; disclosure appears before activation and beside the microphone.

## Sources

The OpenAI Docs skill guided the input-only session and explicit-commit design:
[Realtime transcription](https://developers.openai.com/api/docs/guides/realtime-transcription),
[WebRTC](https://developers.openai.com/api/docs/guides/voice-webrtc?api=realtime),
[client secrets](https://developers.openai.com/api/reference/resources/realtime/subresources/client_secrets).
This is API-powered transcription, not embedding the ChatGPT Voice product or
using its subscription. Device TTS remains the partner's spoken output.

## Acceptance gates

Run Flutter analysis/tests, broker Ruff/pytest, Android release build, and web
release/PWA validation. Test real French speech on the phone after installation:
pauses, restarts, longer answers, noise, final words at Stop, and backgrounding.
Automated transport tests do not establish real recognition quality or account
access to the model. No live paid API call is part of the automated suite.
